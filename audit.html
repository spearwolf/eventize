Was dieses Projekt ist

@spearwolf/eventize macht ein beliebiges JavaScript- oder TypeScript-Objekt zu einem synchronen Event-Emitter. Kein Objekt muss dafür erben oder von einer Klasse abstammen: ein verstecktes, nicht entfernbares Property unter Symbol.for('eventize') trägt die gesamte Maschinerie, und derselbe Aufruf funktioniert auf einem Objektliteral, einer Klasseninstanz und seit v6 auch auf einer Funktion. Der Sinn der Synchronität ist Kontrolle über den Ausführungsfluss — Game-Loops, Echtzeitsysteme, alles, wo ein Event nicht erst im nächsten Tick ankommen darf.

Drei Oberflächen führen auf dieselbe Implementierung: freistehende Funktionen (on(ε, …)), injizierte Methoden (eventize.inject(obj)) und class Eventize. Dazu kommen vier Verhaltensfamilien, die über den simplen Emitter hinausgehen: Wildcards, Prioritäten, aufbewahrte Events (retain) mit Replay an spätere Abonnenten, und Duck-Typing-Dispatch auf Objekte, die gar keine Emitter sind. Null Laufzeitabhängigkeiten, ESM und CJS, opt-in typisierte Event-Maps.

Zusammenfassung der Befunde

Kein einziges Finding der Stufen critical oder high, und keine Memory Leaks — die Referenz-Lifetime ist die am schärfsten durchdachte Achse dieser Codebasis, jeder Splice mit dem Dedup-Index gepaart, jedes Handle mit Emitter und Listener in einem gemeinsam genullten Slot, drei kritische Stellen per WeakRef gepinnt. Das cbt-Gate ist in allen sieben Stufen grün: 34 Suiten, 996 Tests, 100 % Statements.

Was die 19 medium-Befunde eint, ist eine Klasse, keine Zufallsmenge: Zusagen, die der Code nicht mehr einlöst. Die README verspricht Tree-Shaking, ein Bundle mit einem einzigen benannten Import zieht gemessene 96 % der Bibliothek. Ein Doc-Kommentar verspricht bei einer verunglückten Event-Map einen Compilerfehler, tatsächlich fällt der Typ still auf any[] zurück. Zwei Quellen beziffern die Kosten von off(ε, obj) mit „11 ns pro registriertem Event-Namen"; gemessen sind es 122 ms bei 8000 Listenern unter einem Namen, weil die Bucket-Tiefe im Modell gar nicht vorkommt. AGENTS.md erklärt eine einzige Cast zur Regel, es sind vier. Und der Skill, der in fremde Agent-Verzeichnisse symlinkt, nennt eine v6-Verhaltensänderung ausdrücklich „unchanged".

Drei Korrektheitsbefunde wurden ausgeführt statt gelesen: ein Method-Name-Abo ohne Listener-Objekt wird klaglos registriert, überlebt jeden emit und hält über sein Handle den Emitter fest; ein numerischer Eintrag in einem Namens-Array ist registrierbar, aber über off() per Name nicht mehr erreichbar; ein zyklisches Array lässt off() mit RangeError abstürzen, aus einem Aufruf, dessen Dokumentation ausdrücklich zusagt, nie zu werfen. Dazu zwei Pfade, auf denen eine Rejection niemandem gehört und unter Nodes Default den Prozess reißt.
